# 引擎骨架：坐标、场景、底图、前后顺序、渲染

最小可运行版本：`scripts/scroll_demo.py`（无素材、14 秒小样），可复用零件：`scripts/scrollkit.py`。
正式项目在这个骨架上逐层加东西（河道、桥、船、城墙……），层次不变。

## 1. 坐标与尺度

- 网格 (gx, gy) 是地面；`g2s`：屏幕 x = cos30·(gx − gy)，y = 0.5·(gx + gy)；`UP` = (0, −1) 是竖直向上。
- u = gx − gy ∝ 屏幕 x（卷轴方向），v = gx + gy ∝ 屏幕 y（纵深）。功能团、时间都按 u 算。
- 内部像素 = 世界单位 × R。正式片 1080p 用 2× 超采样：R = 2.8，内部 3840×2160，最后 `reduce(2)`。
- 长卷内部宽 `PWI = IW + STEPI × (帧数 − 1)`，3 分钟 1080p 约 4.7 万像素宽——PIL/numpy 都能处理，
  但**整幅 float32 数组一张就 1.2GB**：底图、云气都用 uint8 存、分块（1024–2048 列）计算。

## 2. 场景构建顺序（先占地的先得）

```
桥/大件 → 城墙城门 → 主路/路网 → 河岸步道 → 地标（指定图、指定位置）→ 各功能团的专门建筑
→ 河岸排屋 → 街坊（按功能团选布局：排屋/院落/大宅/广场/寺）→ 摊位带 → 郊野田畦与村落 → 补位（每张图都用上）
→ 树 → 风筝、闲谈人群 → 闲立人物合理性检查 → 路网图（行人寻路）
```

- **占地系统（occupancy）**：每放一样东西登记网格矩形，后来的先查 `occ.hit(rect, pad)`；
  再查 `land_ok`（不压水、所有点在河同侧、离岸 margin）。
- **单一随机数流的陷阱**：整个场景用一个 `Random(seed)` 时，上游任何增删都会让下游全部重新随机——
  加一栋房子可能让风筝消失。对策：各子系统用各自的 `Random(固定种子)`；每次改布局后跑一遍"特征清单"回归（qa.md）。

## 3. 底图烘焙（一次性）

整幅长卷的地面在 setup 时画成一张大图，每帧只裁切。分块向量化：

1. 草/土底色（低频噪声混合，郊野草多）。
2. 路面：土路按走向贴"条带贴图"（沿路坐标 along、横向 lat ∈ [−1, 1]）；**L 形拐角单独成块**，以内角为圆心、
   车辙沿四分之一圆弧转过去，两条条带都截到拐角内侧；丁字/十字路口用无方向的土面。
3. 石板街：**按各自走向铺**（石板顺街）；两街相交时较宽的贯通，交界画一道深色接缝；街外空地压一层淡夯土纹理。
4. 河面、驳岸（错缝石砌）、河岸步道。
5. 投影：所有建筑/树的影子画进一张蒙版、高斯模糊、乘到底图上。

## 4. 前后顺序（画家算法）

- 静态精灵：`(key = 占地前缘的屏幕 y, x, y, 图, 占地矩形)`，setup 后按 key 排序；同时记占地矩形（`tag_foot`），
  动态对象在它前后判断时用。
- 动态对象每帧算 key 插进去（行人 = 脚底 y；船 = 船身中心 y，过桥时把船按桥面切成上下两段分别排序）。
- "画在最上面"的东西（绳子、风筝、炊烟、飞鸟）给极大的 key。**被桥面分层切掉的东西**（如从桥上抛下的缆绳）
  要从船的绘制里拿出来单独成一项。
- 门洞：穿过城门的人画到小图层上、按拱形裁切后再贴。

## 5. 每帧

```
裁底图 → 水纹/雨点涟漪 → 可见静态精灵 + 行人 + 船 + 特效 按 key 排序依次贴
→ 夜色/晨昏调色 + 发光层（只作用于画里的景物）
→ 雨丝 → 卷上的云气（夜里按保护图染色）→ 题字逐字显现 → 题签 → 纸纹相乘 → 卷边 → reduce(SS) → 暗角 → 首尾淡入淡出
```

卷上的东西（云气、题诗、题签、纸纹、卷边）**不属于画里的世界**：不受夜色、天气影响（或只轻染），保证可读。

## 6. 输出与性能

- `preview <秒...>`：出 JPEG（1920×1080 约 0.8MB；要贴给 AI agent 看时单张 ≤5MB，PNG 4MB 一不小心就超）。
- 全片：帧按顺序写进 ffmpeg 管道（libx264 crf 17）。
  180 秒 1080p 的实测（8 进程 `multiprocessing` fork 池，大数组靠写时复制共享）：
  白天 ~20 秒/100 帧，夜景发光层叠加后 ~48 秒/100 帧；全片 22–26 分钟。
  **`scroll_demo.py` 的 `render` 是单进程串行的**（14 秒小样不值得开池）——要这个性能得自己加多进程，
  而且 `fork` 在 macOS（Python 3.8+ 默认 spawn）和 Windows 上不可用：
  那里要么用 `spawn` + 显式把大数组传进子进程（或放共享内存 `multiprocessing.shared_memory`），要么就串行跑。
- 关键数字都打印：精灵数、街段数、行人数、题签数、题字数……出问题时一眼看出哪一层没生成
  （`scroll_demo.py` 的 `setup()` 就是这个格式）。

## 7. 改动的验证节奏

改一处 → `preview` 相关的 2–4 个时刻（只看那一处）→ 必要时孤立测试（例如把船在空白画布上按 9 个角度画一排）→
全片渲染 → `popcheck.py` → `frame_grid.py` 抽帧看。不要每改一处都渲全片。
